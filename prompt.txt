13. PHASE 2: AUTOMATIC NEARBY ROAD DESTINATION

This is the agreed future seller-navigation plan.

Seller sets only the private plant/yard pin.

Backend:
- Generates candidate points approximately 100 metres around that pin.
- Uses Nearest Roads API to obtain road-matched candidates.
- Measures the returned points’ distance from the private location.
- Selects a candidate within a documented acceptable range.
- Saves it as a separate nearby arrival-point cache.

Nearest Roads does not directly mean “find a point exactly 100 metres from the plant.” Do not assume the snapped result remains 100 metres away.

Use approximate straight-line distance terminology, not guaranteed driving distance.

Road matching does not prove truck access, legal stopping, or connection to the plant entrance. Handle unavailable/ambiguous results without inventing a safe destination.

The transporter receives:
- Nearby arrival-point coordinates only.
- “Navigate to nearby arrival point.”
- “Call Admin for final pickup directions.”

Admin retains the private exact plant location.

Do not expose the exact plant as a fallback if road lookup fails.

14. PHASE 2 CACHE AND REFRESH PLAN

Keep Google Roads-derived data separate from the user-confirmed private pin.

Store:
- Nearby latitude/longitude.
- Retrieved-at timestamp.
- Expires-at timestamp.
- Source plant-location version.
- Refresh status and limited retry metadata.

Comply with the applicable Google Roads retention terms. The discussed maximum cache period is 30 consecutive calendar days; verify current terms before implementation.

Do not keep expired coordinates in active records, event payloads, or logs indefinitely. Include retention handling for copies and backups as required.

Refresh rules:
- Reuse valid coordinates.
- Treat a seller with a successful sample upload in the last five days as recently active for this refresh policy.
- This must NOT change the seller’s actual account activation status.
- For recently active sellers, refresh near expiry.
- For a returning inactive seller, trigger refresh after a successful sample upload if the cache is missing/expired.
- Include sellers with ongoing orders even without recent uploads.
- Check/prepare the arrival point at order confirmation or assignment.
- Keep a navigation-click fallback for missing/expired data.
- Delete expired data regardless of activity.
- Do not refresh every inactive seller every month.

A Roads API failure must not fail a sample upload.

Use bounded retries, request deduplication, and one refresh per plant/version.

If the plant pin changes while a refresh is running, reject the stale result.

Use a real scheduled job/worker supported by the deployment environment. Do not assume an unreliable frontend timer or an unconfigured background process exists.

Roads API calls must use a separate backend-only credential, not the browser key.
