Create a new responsive StoneRate Admin page named:

StoneRateAdminUserPartnerDetails.js

PAGE PURPOSE

This page opens when an Admin clicks “View Details” on a record inside:

StoneRateAdminUsersPartners.js

The page must display the complete Admin-authorized profile and operational history of the selected:

1. Buyer
2. Stone Seller
3. Sand Seller
4. Transporter
5. Admin

The page must also allow authorized Admin users to:

- Review identity and Admin verification status
- Verify an account where applicable
- View role-specific business information
- Search the user’s latest orders
- Copy public Request, Delivery, and Transport IDs
- Block an account through double confirmation
- Unblock a blocked account
- Start a highly protected account-deletion workflow
- Review deleted-account status without exposing removed personal information

IMPORTANT DESIGN DIRECTION

Focus heavily on visual quality.

The page must be:

- Attractive
- Stunning

ACCOUNT DELETION SAFETY

The Delete Account workflow is highly destructive.

Do not perform immediate physical deletion from the first button click.

Do not delete records required for:

- Orders
- Deliveries
- Quotations
- Transport assignments
- Disputes
- Financial records
- Security audits
- Legal or regulatory retention
- Fraud prevention

Use controlled deletion and anonymization where complete database deletion would break relational history or business records.

The final outcome required by the interface is:

- Personal profile information removed or anonymized
- Authentication disabled
- Account status set to deleted
- Only the minimum required mobile reference retained, if permitted
- Historical order integrity preserved with an anonymized account reference
- Audit log preserved

The list and details page for a deleted account should show only:

Mobile Number
Status: Deleted

Do not display deleted personal data such as:

- Name
- Email
- Full address
- Aadhaar data
- GSTIN
- Alternate phone
- Profile image
- Business information

DELETION BACKEND TRANSACTION

Perform the final deletion in one database transaction.

The backend should:

1. Lock the account row.
2. Verify the current status.
3. Verify Admin permission.
4. Verify the recent deletion OTP authorization.
5. Prevent deletion of the current signed-in Admin.
6. Revoke active sessions.
7. Anonymize or remove allowed personal data.
8. Remove role-specific non-retained profile data.
9. Set account status to deleted.
10. Store deleted_at.
11. Store deleted_by_admin_id.
12. Store the deletion audit reference.
13. Preserve required relational records.
14. Commit only if every required operation succeeds.
15. Roll back on any failure.

Do not run partial deletion operations outside the transaction.
